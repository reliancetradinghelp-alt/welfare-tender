WeFlare v3 — установка на ваш сервер

В этом комплекте уже написаны новая форма, серверные функции, счётчик, кнопки и установщики. Вручную удалять блоки из bot.py не нужно. Установщик меняет только предусмотренные участки и сохраняет резервную копию.

Используйте архив WEFLARE_V3_RELEASE.zip. Архив с именем CHECKPOINT — промежуточное сохранение, он не предназначен для установки.

Обновление подготовлено для ранее выданной v2, файла /root/bot.py и сайта https://reliancetradinghelp-alt.github.io/welfare-tender/. Если у вас другие пути или изменённая v2, проверка остановит автоматическую замену. Сам сервер из этой переписки не обновлялся.

1. Скачайте и посмотрите результат

  1. Скачайте WEFLARE_V3_RELEASE.zip на компьютер.
  2. Распакуйте архив. Найдите внутри папку weflare_v3.
  3. Откройте START_HERE.html двойным щелчком. Витрина позволяет переключить светлую/тёмную форму и ширину телефона.
  4. Попробуйте подпись: нарисовать → отменить штрих → очистить → вернуть очистку → отметить согласие → отправить. В локальном просмотре данные никуда не отправляются.
  5. Откройте карточки поддержки, конструктора, паспорта и Пульса. В Пульсе показан пример; настоящий сервер начнёт с 235065.

HTML нужно открывать из распакованной папки, чтобы изображения и переходы между файлами работали. Просмотр отдельного файла прямо внутри ZIP может не поддерживать эти связи.

2. Подготовьте момент обновления

Завершите активные диалоги поддержки перед перезапуском. У исходного бота открытые тикеты и кэш восстановления находятся в оперативной памяти. Этот выпуск сохраняет эту модель: при перезапуске открытое состояние не переносится. Сохранённые тендерные заявки и новый индекс остаются в SQLite.

Сохраните текущий tender.html с GitHub на компьютер либо убедитесь, что он есть в истории коммитов. В архиве дополнительно есть baseline/weflare_v2.zip. Это копия ранее выданной v2, а не снимок всех файлов вашего сервера.

Не загружайте на публичный GitHub: настоящий bot.py с токеном, .env, файлы SQLite, папку weflare_backups. Пять файлов в следующем шаге не содержат вашего токена.

3. Загрузите пять файлов на GitHub

Откройте ваш репозиторий: https://github.com/reliancetradinghelp-alt/welfare-tender

Убедитесь, что выбрана та ветка и папка, из которых публикуется существующий сайт. Обычно это main, корень репозитория. Фактическую настройку видно в Settings → Pages. Настройку работающего сайта менять не требуется.

В Code → Add file → Upload files перетащите именно эти файлы:

Для двух Python-файлов откройте папку server на компьютере и перетащите сами файлы. Не перетаскивайте папку server целиком, иначе команды ниже будут искать их по другому адресу.

Нажмите Commit changes, например с сообщением WeFlare v3: design, briefs, pulse, service. Дождитесь успешного обновления GitHub Pages в Actions/Pages. Ничего старого массово удалять не нужно.

Проверьте в обычном браузере три адреса:

Это только просмотр. Уберите preview=1 не вручную, а открывайте боевую форму кнопкой из бота после установки. Старые ссылки без индекса остаются совместимыми с подписью.

4. Скачайте установщики на VPS

Откройте тот терминал, где вы уже управляли ботом. Дальнейшие команды этого раздела выполняются на VPS от root, а не в терминале компьютера.

cd /root
python3 --version
ls -l /root/bot.py /root/weflare_tender.py

Если файлы найдены, скачайте установщики. Команды ниже предполагают ветку main; если в шаге 3 была другая ветка, замените /main/ в обоих адресах её именем.

curl -fL --retry 2 'https://raw.githubusercontent.com/reliancetradinghelp-alt/welfare-tender/main/install_weflare_v3.py' -o /root/install_weflare_v3.py
curl -fL --retry 2 'https://raw.githubusercontent.com/reliancetradinghelp-alt/welfare-tender/main/setup_weflare_service.py' -o /root/setup_weflare_service.py

При 404, 403 или другой ошибке не продолжайте следующими командами: файл не скачан. Проверьте ветку и расположение файлов. Если репозиторий закрытый, не вставляйте токен GitHub в команды: передайте два установщика через уже используемый SFTP-клиент в /root/.

Альтернатива через SCP: в терминале компьютера выполните команду ниже, подставив путь к распакованной папке и IP своего VPS. Она копирует только два установщика, не меняя работающего бота.

scp '/ПУТЬ/К/weflare_v3/server/install_weflare_v3.py' '/ПУТЬ/К/weflare_v3/server/setup_weflare_service.py' root@IP_СЕРВЕРА:/root/

Дальше вернитесь в терминал VPS. Не отправляйте сюда пароль, приватный ключ или токен бота.

5. Проверьте совместимость и установите файлы

Сначала только проверка:

python3 /root/install_weflare_v3.py /root/bot.py --check

Нужен Python 3.9 или новее. Ожидается «ПРОВЕРКА ПРОЙДЕНА». Эта команда не изменяет рабочие файлы и не останавливает бота.

Если написано «отличается от выданной v2» или «структура поддержки отличается», не удаляйте старые файлы и не обходите проверку. Нужна адаптация к вашей текущей копии. Достаточно прислать текст ошибки без секретов; повторная установка старой версии поверх ваших изменений не требуется.

После успешной проверки:

python3 /root/install_weflare_v3.py /root/bot.py

Ожидается «УСТАНОВЛЕНО v3» и путь резервной копии вида /root/weflare_backups/v3-.... Сохраните этот путь у себя.

Установщик:

  • копирует текущий bot.py, заменяемые модули и согласованный снимок SQLite в резервную папку;
  • устанавливает четыре новых модуля рядом с bot.py;
  • подключает оформление оценки/квитанции и защиту от второго процесса;
  • включает режим 24/7, исправляет продолжение текущего клиентского тикета, освобождение блокировки после ошибки и возврат без кэша;
  • сохраняет камеры, список имён, случайный выбор и прежние callback ID оценки;
  • не запускает и не останавливает процессы самостоятельно.

Не редактируйте строки API_TOKEN и не заменяйте свой основной bot.py файлом из чужого примера. В данном архиве полного bot.py намеренно нет: обновляется ваш существующий файл.

6. Запустите одну постоянную службу

Выполните предварительную проверку:

python3 /root/setup_weflare_service.py /root/bot.py

Ожидается «ПРОВЕРКА ПРОЙДЕНА. Ничего не изменено». Покажутся найденные PID, путь Python и будущая конфигурация службы.

Если раньше бот работал в виртуальном окружении, укажите тот же Python. Пример пути ниже условный — используйте путь вашего окружения, а не создавайте новое:

python3 /root/setup_weflare_service.py /root/bot.py --python /root/venv/bin/python

Если проверка с обычным python3 прошла, примените настройку:

python3 /root/setup_weflare_service.py /root/bot.py --apply

Если использовали --python, добавьте тот же параметр и к команде с --apply.

Скрипт проверяет зависимости и генерацию кириллической квитанции до остановки, мягко завершает только процессы, запускающие именно /root/bot.py, создаёт weflare-bot.service и включает её автозапуск. Случайный другой Python-процесс он не завершает. Если бот управляется другой службой, скрипт остановит переключение для разбора конфигурации.

Успешный результат содержит active. После этого проверьте:

systemctl status weflare-bot --no-pager
journalctl -u weflare-bot -n 60 --no-pager

Служба перезапускает процесс при аварийном завершении и запускается после перезагрузки VPS. Она не может сама вылечить неверный токен, отсутствие прав Telegram или недоступную сеть. При постоянной ошибке смотрите журнал.

После этого больше не запускайте этот бот через nohup python3 bot.py или второе окно python3 bot.py. Обычное управление:

Перезапустить после изменения файлов:

systemctl restart weflare-bot

Остановить, только когда это действительно нужно:

systemctl stop weflare-bot

Запустить после остановки:

systemctl start weflare-bot

Для подписи открывайте новую кнопку клавиатуры после /start. Верхняя кнопка меню Mini App — другой режим Telegram; отправка через sendData рассчитана на запуск с клавиатуры. Если клавиатура скрыта, нажмите её значок рядом с полем ввода.

На телефоне дополнительно проверьте светлую/тёмную тему, поворот экрана, отмену штриха и видимость нижней кнопки. Рисунок подписи должен сохраняться при смене темы/размера. Реальные iOS/Android-клиенты при подготовке архива не проверялись.

Если открывается старый дизайн, сначала дождитесь успешной публикации Pages, закройте старую Mini App и получите свежую кнопку через /start. Сервер добавляет параметр версии к URL. Удаление исходников из GitHub не исправляет уже открытое старое окно или второй процесс.

8. Как устроен Пульс

  • Первый календарный день: ровно 235065. Это начальная отметка, поэтому «за день» сначала равно нулю.
  • Со следующего дня: новая прибавка от 50 до 170 по времени UTC+3.
  • 64% выбора диапазона 50–89, 28% — 90–124, 8% — 125–170. Внутри диапазона выбирается число; это не три фиксированных значения.
  • В работающем боте фон проверяет дату раз в 15 минут. /pulse или выдача формы актуализируют данные сразу.
  • Перезапуск, повторное открытие и несколько клиентов не сбрасывают индекс и не повторяют прибавку.
  • Если сервер был выключен, пропущенные дни учитываются при запуске. История до первого запуска не придумывается.
  • Отображается до 28 дней истории, рост за 7 дней, лучший дневной шаг и ближайший рубеж.
  • Экран показывает снимок, а не постоянное соединение с сервером. «Обновить снимок» возвращает запрос боту; он выдаёт новую кнопку с актуальными данными.
  • Индекс обозначен как демонстрационный и не влияет на заявки, оценки или назначение отображаемого имени.

Не удаляйте /root/weflare_tender.sqlite3: там хранятся заявки, черновики, очередь уведомлений и индекс. Его перенос на другой VPS выполняется вместе с ботом и модулями.

9. Эмодзи с вашим логотипом

Файл находится в assets/weflare_check_emoji.webm. Параметры: 100×100, 3 секунды, 30 FPS, VP9, без звука, около 29 KB. Логотип собирается и переходит в фирменную бирюзовую галочку. Это оформление бренда, а не присвоение Telegram-верификации.

Откройте официальный бот https://t.me/Stickers, выберите создание набора эмодзи и видеоформат, затем отправьте WEBM как файл, без преобразования в обычное видео. Следуйте его текущим подсказкам по названию, привязке эмодзи и публикации набора. GIF рядом — только предпросмотр, для загрузки используйте WEBM.

Требования Telegram: https://core.telegram.org/stickers/webm-vp9-encoding

10. Откат к вашей предыдущей версии

Если v3 уже установлена и служба создана:

systemctl stop weflare-bot
python3 /root/install_weflare_v3.py /root/bot.py --rollback
systemctl start weflare-bot
systemctl status weflare-bot --no-pager

Между командами проверяйте результат. Если откат остановился из-за последующих изменений файлов, не запускайте поверх него другие установщики: нужно сопоставить изменения с сохранённой резервной копией.

Откат восстанавливает именно файлы, которые были на вашем VPS перед v3. Рабочая SQLite не заменяется старой копией, поэтому новые заявки не теряются. Дополнительные таблицы остаются; v2 их не использует. В v2 не работают новые /brief, /passport, /pulse и обработчик очереди повторов v3. Неотправленные уведомления остаются в базе до возврата на v3.

На GitHub верните прежний tender.html из истории коммитов или из сохранённой копии. Новые intent.html/activity.html можно оставить, но старая v2 их не обслуживает. Служба systemd остаётся и запускает восстановленный bot.py; отдельный nohup не нужен.

Если настройка службы ещё не применялась, старый процесс продолжает работать. Откат файлов сам по себе его не перезапускает. Если ошибка возникла во время переключения и служба не запустилась, сначала сохраните вывод установщика и journalctl: часть шагов могла уже выполниться. Не запускайте несколько копий «на всякий случай».

11. Если нужна помощь после установки

Для разбора достаточно текста ошибки, результата systemctl status weflare-bot --no-pager и последних строк журнала. Перед отправкой закройте токены/секреты, если сторонняя библиотека напечатала их в исключении. Номер чужой заявки и рисунок подписи для диагностики не нужны.

Камеры, внешние подключения и полноценная многопользовательская панель операторов не входят в этот выпуск. Функции бота, формы, конструктора, паспорта и индекса запускаются описанной установкой; проверка настоящего Telegram завершает её.

Основа способа отправки Mini App: https://core.telegram.org/bots/webapps#keyboard-button-mini-apps
